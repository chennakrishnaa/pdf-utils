# Independent review, round 2 (FH)

Reviewed commit `1f242ad` (main), compared with `7c23a9c` (the build the owner tested).

## Verdict
1. **Private trial: yes, after one fix.** The security posture still holds on both APKs: no permissions, only `MainActivity` exported, backups off, and no network code. H1, H2, M1 and M2 are fixed in code and covered by host tests.
2. **New High (N1):** the M4 truncation check rejects valid JPEGs that carry more than 64 KiB of data after the end-of-image marker. Motion photos are built this way (Pixel "Motion", Samsung). Such photos fail in Images to PDF and Add images with "image not supported", and they blank every size estimate.
3. **Wider distribution: still no.** B1 (placeholder AGPL source URL) and M6 (third-party notices) are not addressed. The release build is unsigned and has never run. None of this round's changes has run on a device beyond the conductor's smoke test.

Checked and found correct: `viewIntent` and `shareIntent` grant read access only, `clipData` is set on the share intent, and `createChooser` propagates it. "Clear" and "Remove" only edit the list and release grants; they never delete documents, and Clear asks for confirmation. Saving the same Uri twice moves its entry to the top without duplicating it. The store holds only Uri, name, size, time and tool id, in private preferences excluded from backup. Store access from `HomeViewModel` and `JobViewModel` runs on `Dispatchers.IO`. Corrupt JSON gives an empty list (`RecentFilesStoreTest.corruptStoredDataIsEmpty`). `encodeJpeg` and `estimate` destroy every `Pixmap`, `DrawDevice`, `Buffer`, `Image` and `PDFObject`, and the colour-space singletons are never destroyed. Estimates run on the single engine dispatcher and delete their job directory in `finally` (`PdfJobsTest.estimateImage*`). The "never larger" rule holds at the image level (probe: High gave an 86 KB output from a 1.1 MB input; estimates are capped at the original size). EXIF 6 stays upright at every level (`ImagesToPdfOpTest.exifOrientation6IsUprightAtEveryLevel`). Icon buttons are 48 dp and have content descriptions.
